# Cleaner workspace design QA

- Date: 2026-08-08
- Target: `http://127.0.0.1:1420/?prototype=cleaner`
- Final result: passed

## Verified

- 首页默认进入 A 任务卡布局，并显示风险优先的快速清理摘要。
- 点击“空间分析”进入 B 语义空间地图，空间块、风险图例和右侧解释面板同时可见。
- 三个页面都使用同一套左侧主导航；导航位置不会随页面职责变化。
- 点击“深度清理”进入 C 深度清理 / 执行前审核工作台，筛选、逐项选择和清理计划可见。
- 首页、空间分析、深度清理之间可往返导航，导航状态会同步到 `surface` URL 参数。
- 导航项统一显示“深度清理”；“专项包”仅保留为内部规则包概念，不作为用户入口文案。
- 旧的 `variant=B` 链接仍会映射到空间分析，避免已有评审链接失效。
- 从空间分析进入“复核”可打开人工审核抽屉；高风险内容不会进入默认选择。
- 初始页面保留内存演示数据；点击“重新扫描”后，A/B/C 会共用 `api.scan` 返回的扫描树和现有本地候选规则。
- 扫描结果中的已审核低风险 scope 才会默认选择；未审核低风险范围降级为“需要确认”，用户内容和系统路径保持“仅建议查看”。
- 执行按钮仍只模拟隔离，不执行真实删除命令。

## Limits

- 历史 / 恢复和设置仍是占位页面，待生产数据与设置模型接入后补齐。
- 浏览器回归使用 `api` 的模拟扫描树；尚未在真实 Windows 磁盘上验证扫描耗时、权限回退或执行器行为。
